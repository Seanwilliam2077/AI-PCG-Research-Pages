01

白盒生成管线与批量生产

这条管线的目标是把关卡白盒搭建从纯手工变成 AI 生成为主、人工调整为辅:一张概念图进,一个可游走的白盒关卡出,把前期搭建从天级压缩到分钟级——再把它变成夜跑几百个场景的生产线,让白盒从单个 demo 变成可规模化供给的资产来源。

① 生图

三图供给

文生图双通道产写实航拍、语义分块、灰度高度三图;提示词模板锁定 90° 正交顶视,支持笔刷蒙版 + 文字指令的局部重绘。

② 矢量化

语义图 → 布局数据

按语义色提取建筑 / 道路 / 植被 / 水体 / 边界轮廓;另有精度优先通路直接产内存布局文档;角色比例节点推算真实世界尺度。

③ 落地

Create PCG Data

高度图写入 Landscape,布局数据生成街区、地块与建筑白盒;统一摆放节点生成植物、围墙与道路。地形与街区共用同一标定,严格对齐。

工程要点

分帧执行。写高度、生成街区、贴回地形分帧进行,等碰撞就绪才吸附地块——编辑器全程可重绘不假死。

统一标定。一个目标宽度同时推导地形缩放与布局单位,街区与地形像素级对齐,且与高度图分辨率解耦。

失败隔离。高度图与街区两路互不阻塞,状态聚合后统一广播;材质层资产缺失时自动创建。

统一摆放。植物 / 围墙 / 道路一个节点分派,规则可按 job 覆盖:贴地、坡向对齐、陡坡 30° 禁植、崖边禁植。

BatchPCG — 无人值守批量

关键节点全部无头化(五个 Python 入口 + 重置与收敛轮询),三阶段编排:云端生图 → 编辑器内状态机 → 汇总报告。每 25 个 job 重启编辑器规避内存累积,断点续跑、失败熔断、启动预检、离屏后台真 GPU 渲染——维护一份 prompt 清单即可夜跑。「万能顶视图框架」由 LLM 按主题产异质化组合,近无限 prompt 供给。

02

GeoGen — 山体与植被生成

GeoGen 补齐大世界的地形与生态环节:白盒解决街区,山体与植被此前仍靠手工雕刻。地形 / 蒙版 / 城市 / 工具四套面板收进一个编辑器模式——观感对齐 Modeling Mode,机制自绘,三套既有业务逻辑一行未改;近中景与远景两条路线各持一套流水线节点,反复调远山不会覆盖近景结果。

山体 — 一键生成链

STEP 1 · 环绕参考图

多张参考图 AI 合成「中央平地、四周环山」俯视图;笔刷蒙版 + 文字指令局部重绘,未涂抹像素逐字节保真。

STEP 2 · AI 高度图

让图像模型按海拔推理成图:雪线读作高地、河谷读作最低;多图按生态特征排序,要求产出一块连续地形而非拼贴。

STEP 3 · 侵蚀与生态蒙版

服务器侵蚀(1K 约 20 秒 / 2K 约 90 秒);生态蒙版刻意排在侵蚀后,沿真实冲刷纹理划分植被、岩石与积雪。

四步产物全是图片、零副作用可无限重来;写地形、放图章、交接 Genesis 都刻意留在链外。

近中景落地

地形面积由用户直接指定(上限 2500 km²),每格尺度在生成那一刻现算,切分辨率档不再让面积漂移;幂等备好尺寸缩放都对的空地形,高度落差靠 Scale.Z 兑现;边界包络坡角只削戳破包络处、内部分毫不动;交接 Genesis 时高度图与 16 色生态蒙版按地形顶点数对齐导出,省掉破坏性确认框。

远景产物

默认烘成单一连续静态网格,移动旋转复制全是引擎原生行为;可选独立 Landscape 或地形图章(挪动自动重刻、删除自动还高度);「提取山峰」逐座抠峰散布地平线;显存策略用尺度换覆盖——同顶点数从 2 km 拉到 8 km,显存完全不变。

植被生成

生态分布图双来源(近中景 / 远景山)各持独立结果;16 色蒙版一键导入 Genesis 为每层绑定 PCG Graph,缺图登记直接在面板显示;植被生成只跑 VegetationOnly 阶段、不改地形高度,与山体侧「只跑权重图章」互为镜像。摆放规则与批量管线同源:贴地、陡坡 30° 禁植、崖边台缘禁植。

03

世界模型 — 数据采集与视频批产

出发点是把批量白盒变成世界模型的训练数据:在白盒之上自动运镜、无损渲染、坐标转换,产物按数据集契约落盘,连成一条无人值守生产线。五阶段全部用编辑器内 Python 实现,不动 C++、不碰节点管线。

程序化运镜

建筑群包围盒定轨道,orbit / dolly / crane 模版按 job 随机;内参与对焦显式固定,位姿按轨迹参数解析重算,无采样误差。

MRQ 无损渲染

固定曝光、关运动模糊、空间采样抗锯齿;RGB 之外输出 32 位深度与法线,逐帧位姿写入 cameras.json 作数据真源。

坐标转换与打包

UE 约定转 OpenCV 相机约定并以合成位姿单测;深度换米、内参换算 K;全部产物校验后按目录契约落盘,下游直接组装。

47.5 s

单场景「生图 → 白盒 → 运镜 → 成片」全链耗时——离屏无人值守实测(2026.07.22),48 帧 mp4 落盘、截图非黑。一键视频批产:浏览器输入 fps / 数量 / 时长即自动跑完全链,动态容量按质检现算,拍满即切、拍够即停。

04

前沿探索 — 游戏场景 3DGS 重建

探索把游戏场景变成 3DGS 表达:不涉及真实设备,数据全部来自引擎内——沿烘焙 probe 点连线生成采集路径自动采数据,重建为可在编辑器内查看的 3DGS 资产,并完成定制引擎的渲染集成验证。采集管线已迭代约 20 次,单轮采集很快;当前重建质量还不够好,瓶颈集中在两处,仍在迭代。

问题 1 · 曝光一致性

暗区场景明暗差距大:统一曝光会让暗部死黑、看不清细节纹理;自动曝光又会让同一区域在不同帧曝光不一致,重建质量更差。暂定思路是采下 HDR 数据后做统一后处理——同一套曝光,把暗部拉亮一些、亮部稍微压缩。

HDR 采集 → exposure 调整整体亮度 → tone mapping 压缩动态范围 → gamma / sRGB 转换

问题 2 · probe 采集路径

部分 probe 点离墙面过近,影响重建质量。优化方向是按 probe 特性把点整体向后拉,尚未完成最终调整;计划先采完暗区场景再统一对齐,预计还需几轮迭代。
